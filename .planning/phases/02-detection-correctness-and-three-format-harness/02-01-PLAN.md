<planner_decisions>
Choices `02-CONTEXT.md` left to the planner, settled here once for the whole phase.

1. **The pure loaders move to `qc/loaders.py` in this plan.** Phase 1's D-08 parked loader
   extraction explicitly for this phase, on the grounds that separating pure parsing from the
   caching wrapper is real work and that Phase 2 changes loader behaviour anyway through INTEG-01
   and INTEG-03. `02-CONTEXT.md`'s Integration Points repeats it. It is also what makes ENGINE-06
   real: `app.py` cannot be imported from a test, because its module body calls
   `st.set_page_config` and `st.markdown` and fails outside a Streamlit runtime, as
   `tests/fixtures.py`'s own docstring records. Without the extraction the golden fixture would
   have to re-implement the loaders and would prove nothing about the code that actually runs.

2. **Which load paths normalisation covers** (plan 03): the MLoS frame, the Takeoffpoint frame from
   the same upload, and the separately uploaded Takeoffpoint file. Not the two bundled boundary
   reference CSVs — they are repo-controlled files whose headers are already canonical, so
   normalising them is defensive rather than required. One helper, `qc.columns.normalize_columns`,
   is used at every applied site, which is what makes INTEG-03's "normalised once" true.

3. **`Failing Rows` and `Total Rows` for the three run-level checks.** `S3` follows `S1` and `S2`'s
   column-count denominator: `Failing Rows` is the number of colliding groups and `Total Rows` is
   the number of original headers examined. `B4` and `B5` are binary run-level conditions with no
   honest column-count denominator, so both report 1 over 1 — one finding out of one possible
   finding. Research recommended exactly this and `02-CONTEXT.md` left it open.

4. **`tests/test_extraction_parity.py` becomes hand-derived, not a second frozen JSON.** Research's
   Open Question 1 recommended option (a) and the orchestrator agreed. The shape chosen here goes
   one step further so that this plan is the only plan that edits the file: the comparison is
   scoped to the intersection of the frozen baseline's identifiers and the live registry; any
   identifier the live engine emits that the baseline does not carry must be registered, so a stray
   unregistered check still fails; and each identifier whose value Phase 2 deliberately moves is
   declared in one table with its requirement and decision reference. Plans 02 through 05 then
   assert their new identifiers in their own new test files and never touch this one. Without that
   scoping, `tests/test_extraction_parity.py` would be shared across four plans and would force
   every plan into its own wave for the wrong reason.

5. **The shared 10-row fixture is not modified.** Pitfall 2 is real: the existing fixture has no
   genuinely blank cross-table cell, so nothing would prove the `.missing` checks detect a blank.
   But adding rows to `build_mlos_fixture` changes `Total Rows` for every check in every layer and
   invalidates the frozen baseline wholesale. Plan 02 therefore adds separate builders used only by
   the new `.missing` tests. Pitfall 2's substance is fully satisfied; its suggested method is not,
   and the reason is recorded here.
</planner_decisions>

empty string, whitespace-only, or one of the case-insensitive sentinels null, none, n/a, nan and a
bare hyphen. The sentinel list applies to every column. The single exemption is the exact literal
NA, matched case-sensitively.

**Why the exemption cannot be per-column.** NA is a valid value in the nine flag columns and it is
also Nasarawa's state_code. FLAG_COLS does not contain state_code, so a per-column carve-out would
need two unrelated lists kept in sync. The single global case-sensitive exemption is one rule.

**The consequence you are accepting, stated plainly.** A cell containing the three characters N,
slash, A in a flag column now reads as absent and fires Rule 1, instead of reaching Rule 12 and
being flagged as an invalid flag value. The finding still appears; it appears under a different
rule. Lowercase na reads as present, because it is not in the sentinel list — a different string
from nan.

**Why it is one-way.** Reversing after real submissions are scored moves Rule 1, the six `.missing`
findings and B0's failing-row counts at the same time, and any report already filed disagrees with a
rerun. There is no migration for a Nasarawa file already scored under a broken exemption.
