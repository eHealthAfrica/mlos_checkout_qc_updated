<objective>
Close INTEG-04: the boundary reference's scope becomes a reported fact rather than a silent branch.

Purpose: at `qc/boundary.py:89-91`, when state-name filtering yields nothing, both `filtered_ref`
and `filtered_bbox` are reassigned to the full national set and `B1` and `B2` then validate against
all 9,410 wards instead of the file's own state — with no warning channel at all, because
`run_ward_boundary_qc` returns only checks and details. That is defect F13. Separately, when the
bundled reference files are absent entirely, `B1`, `B2` and `B3` all silently fail to emit and only
`B0` runs, so a run with no reference looks like a run with nothing to report.

Output: two new registered checks — `B4` for the widening and `B5` for an unavailable reference —
canonical boundary order extended to `B0` through `B5`, the sidebar reference rows that document
them, a standing three-state invariant test, the registry-coverage guard extended so it can
actually reach `B5`, and `README.md`'s State filtering paragraph brought in line with the new
behaviour.
</objective>

The `assumption-delta` probe fired on this phase with one `pluralization` signal, on the term
"fallback" in success criterion 5. Advisory and non-blocking; recorded here because this plan is
where the delta lands.

**The noun that is now primary: the scope of the boundary reference.** Before this phase the
reference was one implicit thing — `filtered_ref`, state-filtered, with widening as an unnamed side
effect of an `if`. After D-16 through D-19 it has three named states: state-scoped, nationally
widened, and unavailable.

**Decision: promote.** D-16 through D-19 already promote reference *scope* to a first-class
reported fact, `B4`, and reference *availability* to another, `B5`, rather than leaving the widening
as a silent branch. No change to the identity model itself — `ward_code` remains the join key
between the submission and the reference, and nothing about that is revisited.

**Sanity-checked against the code.** Verified this planning session by running the three scenarios
against the real bundled reference: a state-matched run emits `B0`, `B1`, `B2`, `B3`; a run whose
`state_name` matches no reference row empties the state filter, fires the fallback, and still emits
`B0`, `B1`, `B2`, `B3` with no signal that the scope changed; and a run with empty reference frames
emits `B0` alone. The join key is `ward_code` in all three. The promotion is additive, not a
remodelling.

**Companion invariant test — adopted, not merely recommended.** Task 1 creates
`tests/test_boundary_reference_states.py`, asserting that the emitted boundary check set is exactly
`B0, B1, B2, B3, B4` when state-matched with `B4` reporting PASS, exactly the same five with `B4`
reporting FAIL when widened, and exactly `B0, B5` when the reference is absent. That test goes red
the instant a future phase reintroduces silent widening. It also satisfies the `B5` second-scenario
gap that `tests/test_registry_covers_emitted_ids.py` cannot reach on its own.
