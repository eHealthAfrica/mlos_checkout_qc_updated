  <action>
    Wire the single happy path through every layer this phase touches, production quality, no
    other call sites.

    **`qc/secrets_materializer.py`** (new, pure, no `import streamlit`, no `os.environ` read
    inside the pure functions — the environment is always injected as a mapping argument, per
    `qc/columns.py`'s avoidance of ambient state). Module docstring states what it does NOT do
    (no live environment access, no Streamlit import, no file I/O) and names the bug class it
    exists for: Streamlit loads `secrets.toml` lazily on first access, and that first access can
    be triggered by an unrelated earlier `st.*` call, so a materialiser that runs late is a
    materialiser that never ran (D-01, Streamlit issue #10543). Define
    `AUTH_ENV_KEYS = ("REDIRECT_URI", "COOKIE_SECRET", "GOOGLE_CLIENT_ID", "GOOGLE_CLIENT_SECRET")`
    as a tuple, in the order they are emitted, and
    `GOOGLE_METADATA_URL = "https://accounts.google.com/.well-known/openid-configuration"`.
    `missing_auth_env_keys(env)` returns the sorted subset of `AUTH_ENV_KEYS` whose value is
    absent, `None`, or whitespace-only. `auth_env_is_complete(env)` is
    `not missing_auth_env_keys(env)`. `build_secrets_toml(env)` returns `None` when the
    environment is incomplete, otherwise a string holding a single `[auth]` table with the five
    keys `redirect_uri`, `cookie_secret`, `client_id`, `client_secret`, `server_metadata_url`
    emitted in that fixed order and each value TOML-escaped (use `json.dumps` on the string value
    — TOML basic strings and JSON strings share escaping for the characters that can appear in
    these values, and a raw f-string interpolation would break on a secret containing a quote or
    backslash). Fixed key order is load bearing: it is what makes the render deterministic and
    therefore what makes the change-detecting write in `auth.py` correct.

    **`qc/auth_domain.py`** (new, pure, no `import streamlit`). Module docstring records the
    rejected alternative inline the way `qc/columns.py` does: a domain allow-list and an explicit
    email allow-list were both offered during discussion and NOT chosen (D-04), so a later
    contributor must not "simplify" the exact single-domain check into a membership test.
    `ALLOWED_DOMAIN = "ehealthnigeria.org"`. `extract_domain(user)` takes a plain object or
    mapping — never `st.user` by type — reads the `hd` claim first, falls back to the text after
    the last `@` in `email`, lower-cases and strips, and returns `""` when neither yields a
    domain. Read both claims through one small accessor that tries mapping subscription then
    attribute access, so a dict, a `SimpleNamespace` and `st.user` all work.
    `is_authorized_domain(domain, allowed=ALLOWED_DOMAIN)` compares the two case-folded stripped
    strings with `==` and nothing else — no `endswith`, no `in`, no suffix logic; that is the
    whole point (D-04). `bypass_requested(env)` returns True only when the environment's
    `MLOS_AUTH_DISABLED` value, stripped and lower-cased, is one of `1`, `true`, `yes`; the empty
    string, whitespace, `0`, `false` and an absent key are all False. Define
    `OUTCOMES = ("unconfigured", "bypass", "signin", "refused", "allowed")` and a frozen
    dataclass `AccessDecision` with fields `outcome: str` and `flag_ignored: bool`.
    `decide_access(*, configured, bypass, logged_in, domain, allowed=ALLOWED_DOMAIN)` is
    keyword-only and implements exactly this table, with `flag_ignored = configured and bypass`
    in every row:

    | configured | bypass | logged_in | domain vs allowed | outcome |
    |---|---|---|---|---|
    | False | False | any | any | `unconfigured` |
    | False | True  | any | any | `bypass` |
    | True  | any   | False | any | `signin` |
    | True  | any   | True | not equal | `refused` |
    | True  | any   | True | equal | `allowed` |

    Note the deliberate asymmetry: `bypass` is reachable only when configuration is absent. A
    deployed Space that has real `[auth]` configuration can never be opened by someone setting
    the opt-out variable — it only raises `flag_ignored`, which the gate surfaces as a warning
    (D-03; this is the structural answer to RESEARCH Pitfall 4).

    **`auth.py`** (new, repo root, thin Streamlit-touching module). Follow `app.py`'s em-dash
    section-banner convention (`# ─── Section ───…`) for its two or three sections. Docstring
    states "thin gate only" and names the pure modules that own the logic, the way
    `send_qc_email`'s docstring names `qc.report`. Define
    `SECRETS_PATH = Path(".streamlit") / "secrets.toml"`, `BYPASS_ENV_VAR = "MLOS_AUTH_DISABLED"`,
    `CONTACT_ENV_VAR = "DATA_TEAM_CONTACT"`.
    `secret(key, default="")` reads `os.environ[key]`, then `os.environ[key.upper()]`, then
    `st.secrets.get(key, default)` inside a `try/except Exception` so a missing or unreadable
    secrets file falls back to the default instead of raising — Hugging Face Spaces injects flat
    environment variables that `st.secrets` does not see (RESEARCH assumption A2), and the
    existing lower-case keys such as `smtp_host` must keep resolving from a local
    `.streamlit/secrets.toml` unchanged.
    `materialize_auth_secrets(env=None)` defaults `env` to `os.environ`, calls
    `qc.secrets_materializer.build_secrets_toml`, returns `False` immediately when it gets
    `None`, and otherwise creates `.streamlit/` with `parents=True, exist_ok=True`, compares the
    rendered text against the file's current content when the file exists, writes only when they
    differ, and returns `True`. The comparison is not an optimisation: this function runs at
    module scope on every Streamlit rerun, and an unconditional write changes the file's mtime,
    which Streamlit's own secrets file watcher observes and turns into another rerun.
    `auth_is_configured(env=None)` delegates to `auth_env_is_complete`.
    `require_login()` gathers the four inputs — `auth_is_configured()`,
    `bypass_requested(os.environ)`, `bool(getattr(st.user, "is_logged_in", False))` guarded by
    `try/except Exception` so an environment without a session context resolves False rather than
    raising, and `extract_domain(st.user)` under the same guard — calls `decide_access`, then
    renders `st.warning` naming `MLOS_AUTH_DISABLED` when `decision.flag_ignored`, and branches:
    on `allowed` return `current_officer()`; on `bypass` render the banner and return `None`; on
    every other outcome render that outcome's screen and fall through. The **last statement of
    the function body is a bare `st.stop()`**, reached by exactly the three stopping outcomes;
    the function contains exactly two `return` statements. That shape is what the standing test
    asserts, and it is what makes "no branch falls through to the uploader" a structural
    property rather than a review opinion.
    `current_officer()` returns `None` when not signed in, else a plain dict with keys `email`,
    `name` and `domain` read off `st.user`. This is the accessor Phase 5's submission log
    consumes; nothing else in the codebase may reach into `st.user` directly.
    In this task implement only `render_signin_screen()` — a heading, one sentence naming the
