<assumption_delta_decision>
The `assumption-delta scan` probe returned `detected: true` with one `pluralization` signal on
the Phase 1 roadmap text. Reviewed, and there is a real identity-model change underneath it —
though not the one the matched word points at.

- **The noun that is now primary:** the **registered `Rule`**. Until now rule identity was a
  bare string literal minted at each `add()` call site, with five copies of that call site and
  no shared definition. From this plan on, a `Rule` record — identifier, layer, name,
  description — is declared once at import time and the `"Rule#"` value carried on a check
  dictionary is a *reference to* that record rather than the record itself.
- **The decision:** `promote`. The registry becomes the primary identity and the call-site
  string is demoted to a lookup key into it. Explicitly not `add-alongside`: leaving the
  call-site literal authoritative while adding a registry beside it would let a layer emit an
  identifier no one declared, which is exactly the state that made the duplicate-numbering
  defect invisible for as long as it was.
- The singular-to-plural transition is real and concrete: identifiers 11 and 12 each named one
  check and now name three and eight respectively. That is what forces the registry to own
  identity rather than the loop that emits the checks.
- **Companion invariant test:** accepted, and scheduled in plan 06 as
  `tests/test_registry_covers_emitted_ids.py` — every identifier any layer emits must resolve to
  exactly one registered `Rule`, and the fixture must emit every registered identifier. That
  test goes red the moment a future phase reintroduces a call-site literal nobody declared.
</assumption_delta_decision>
